# Render (temporary API and web hosting)

Render hosts the **same Docker images** that run on the production PC. The
blueprint is [`render.yaml`](../render.yaml); nothing in the application is
Render-specific.

Status: **prepared, not deployed** — it needs the owner's Render account
(free plan, no card) connected to the GitHub repository.

## Services

| Service | Image | Health check | Notes |
| --- | --- | --- | --- |
| `iraq-proptech-api` | `backend/Dockerfile` | `/api/v1/health` | Runs `preflight`, then `alembic upgrade head` (`RUN_MIGRATIONS=1`), then uvicorn on `$PORT` |
| `iraq-proptech-web` | `frontend/Dockerfile` | `/` | Next.js standalone server on `$PORT`; proxies `/api/v1/*` to `API_INTERNAL_URL` |

## Deploy

1. Render dashboard → **New → Blueprint** → select this repository. Render
   reads `render.yaml` and creates both services on the free plan.
2. Fill the values marked `sync: false`:
   - API: `DATABASE_URL` (Supabase session pooler URI, [SUPABASE.md](SUPABASE.md)),
     `S3_ENDPOINT_URL`, `S3_REGION`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`
     (Supabase Storage S3 connection), `DEMO_ACCOUNT_PASSWORD` (demo accounts).
   - Web: `API_INTERNAL_URL` — the API service URL, e.g.
     `https://iraq-proptech-api.onrender.com` (correct it if Render adds a suffix).
3. `JWT_SECRET` and `JOBS_TRIGGER_TOKEN` are generated by Render. Copy
   `JOBS_TRIGGER_TOKEN` into the GitHub secret `JOBS_TRIGGER_TOKEN`; also add
   `SUPABASE_DB_URL` and `DEMO_ACCOUNT_PASSWORD` as GitHub secrets
   ([ONLINE-LAUNCH-STATUS.md](ONLINE-LAUNCH-STATUS.md)).
4. Put the two public URLs into [`deploy/live.env`](../deploy/live.env). From then
   on every deploy is verified by the **Live site** workflow; manually:

```bash
scripts/deploy/smoke.sh https://iraq-proptech-web.onrender.com https://iraq-proptech-api.onrender.com
```

`DEMO_SEED=iraq` makes the API seed the national DEMO dataset in the background
at start-up (idempotent); set it to `off` to stop.

The API refuses to start if `python -m app.cli preflight` finds a
configuration error (wildcard or `http://` CORS origins, insecure cookies,
an AI/SMS/S3 provider selected without credentials, …). Warnings (mock email,
demo payments) are printed in the deploy log.

## Free-plan behaviour and how the app handles it

| Free-plan property | Handling |
| --- | --- |
| Instances sleep when idle; the first request wakes them (slow) | The smoke test and the jobs workflow retry with back-off |
| No free background workers / cron jobs | `NOTIFICATIONS_INLINE=true` delivers notifications after each commit in the API process; scheduled jobs run via `.github/workflows/scheduled-jobs.yml` calling the token-protected `POST /api/v1/internal/jobs/run` |
| No free Redis in the blueprint | Rate limiting falls back to a per-process in-memory window; readiness reports Redis as `unavailable` (status `degraded`, still serving) |
| Ephemeral disk | Media on Supabase Storage (`STORAGE_BACKEND=s3`) |
| Free services cannot use the private network | The web service reaches the API over HTTPS; client IPs pass through two Render edges, hence `TRUSTED_PROXY_HOPS=2` |

Free-plan terms change over time; check Render's pricing page and never
upgrade a service plan without deciding to pay.

## Scheduled jobs

`.github/workflows/scheduled-jobs.yml` runs every 30 minutes (GitHub Actions
cron is free for public repositories and within the free minutes for private
ones). It wakes the API, then calls the job trigger with the
`X-Jobs-Token` header. Without the two secrets the workflow exits successfully
and does nothing. The endpoint answers 404 when the token is not configured or
does not match, so it cannot be discovered.

## Demo payments

The blueprint sets `PAYMENT_DEMO_IN_PRODUCTION=true` because the temporary
site is a public demonstration: checkouts are simulated, marked DEMO
everywhere, and no money moves. Remove it (or set `PAYMENT_PROVIDER=none`)
for anything that is not a demo.
