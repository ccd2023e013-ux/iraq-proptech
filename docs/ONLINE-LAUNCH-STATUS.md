## Architecture used for the launch (unchanged application)

| Layer | Service (free tier) | Configured in |
| --- | --- | --- |
| Web (Next.js, Arabic RTL) | Render web service `iraq-proptech-web` (Docker) | [`render.yaml`](../render.yaml) |
| API (FastAPI) | Render web service `iraq-proptech-api` (Docker), migrations at start-up | [`render.yaml`](../render.yaml) |
| Database | Supabase PostgreSQL + PostGIS + pg_trgm (session pooler, IPv4) | [SUPABASE.md](SUPABASE.md) |
| Photos / documents | Supabase Storage, private bucket `media`, S3 API | [SUPABASE.md](SUPABASE.md) |
| Background jobs | no free worker: notifications inline after commit + hourly GitHub cron → token-protected jobs endpoint | [`scheduled-jobs.yml`](../.github/workflows/scheduled-jobs.yml) |
| Maps | MapLibre + OpenFreeMap vector tiles (free, no key) | `MAP_PROVIDER=openfreemap` |
| AI | MockAI (clearly labelled simulation) + statistical analyses from platform data | `AI_PROVIDER=mock` |
| Email | mock (not sent) until an SMTP sender is configured | optional |
| CI / CD | GitHub Actions; Render auto-deploys `main`; the **Live site** workflow verifies every deploy | [`live.yml`](../.github/workflows/live.yml) |

Cloudflare Pages is not used (see [CLOUDFLARE.md](CLOUDFLARE.md)).

## Required environment variables

**Render — `iraq-proptech-api`** (entered in the Render dashboard; never committed)

| Key | Value | Set by |
| --- | --- | --- |
| `DATABASE_URL` | Supabase **session pooler** URI (port 5432) | owner |
| `S3_ENDPOINT_URL`, `S3_REGION`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` | Supabase Storage S3 connection | owner |
| `DEMO_ACCOUNT_PASSWORD` | strong password for the 5 demo accounts | owner |
| `JWT_SECRET`, `JOBS_TRIGGER_TOKEN` | generated by Render | automatic |
| everything else (`APP_ENV=production`, `RUN_MIGRATIONS=1`, `DEMO_SEED=iraq`, `STORAGE_BACKEND=s3`, `S3_BUCKET=media`, `AI_PROVIDER=mock`, `TRUSTED_PROXY_HOPS=2`, `NOTIFICATIONS_INLINE=true`, pool sizes) | fixed in `render.yaml` | automatic |

**Render — `iraq-proptech-web`**: `API_INTERNAL_URL` = the API's `https://…onrender.com` URL (owner); map settings fixed in `render.yaml`.

**GitHub repository secrets** (Settings → Secrets and variables → Actions)

## Demo content and accounts

- `DEMO_SEED=iraq` seeds, in the background at API start-up and idempotently,
  **126 synthetic listings** (18 each in Basra, Baghdad, Najaf, Karbala, Erbil,
  Mosul, Sulaymaniyah), each `is_demo = true`, titled "إعلان تجريبي"/"DEMO",
  with a disclaimer in the description and a generated illustration labelled
  "DEMO — SYNTHETIC IMAGE". Areas are approximate demo squares
  (`geometry_source` = DEMO), a few named after well-known districts with
  approximate centres, the rest explicitly synthetic ("المنطقة الشمالية
  (تجريبية)"). Demo schools/hospitals/mosques/markets are marked "DEMO — not a
  real place".

  `demo.admin@example.com` (ADMIN), `demo.agency@example.com` (agency owner of
  the verified demo agency "مكتب الرافدين العقاري (تجريبي)"),
  `demo.agent@example.com` (agent), `demo.owner@example.com` (private
  owner), `demo.customer@example.com` (customer).

## Known limitations of the free launch

- Free Render instances sleep after ~15 minutes without traffic; the first
  visit then takes up to about a minute. Free instance hours are limited per
  month (check Render's pricing page); the hourly job keeps usage moderate.
- Supabase free projects pause after a period of inactivity; the hourly job
  touches the database to avoid that.
- Without an SMTP sender, new users can register and sign in but cannot verify
  their email, so inquiries and new listings by *new* users wait for email
  verification; the demo accounts are verified.
- No Redis on the free plan: rate limits are per instance (in memory); the
  readiness endpoint reports Redis as `unavailable` (status `degraded`).
